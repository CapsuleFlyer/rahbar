# Part E — drift and semantic coverage

## E1 — live query set

`eval/coverage_queries.json` contains 40 live-style queries: 28 in-domain questions
related to the golden set and 12 out-of-domain questions.

## E2 — live-query to golden-question semantic coverage

E2 is measured by embedding every live query and every golden question with the same
embedding model, then finding the highest cosine similarity between each live query and
the complete golden-question set. This is distinct from checking whether a retrieved
document appears in the top-k results.

The threshold is **0.85 cosine similarity**. This follows the assignment paper's example
of flagging a coverage gap when fewer than 85% of live queries reach the similarity
threshold. The gate requires at least 85% of in-domain queries to reach it. The report
also lists each query's nearest golden question and groups uncovered in-domain queries
by topic. Out-of-domain matches are reported separately because they are not expected
to be covered by the domain golden set.

Build and load the updated evaluation image after changing the script:

```bash
docker build -t rahbar-eval:dev eval
minikube image load rahbar-eval:dev
```

Run E2 from the cluster. The evaluation Job can reach the Ollama embedding container
through the same `OLLAMA_URL` ConfigMap setting used by Part B:

```bash
make live-coverage
```

The command saves `eval/coverage/live-coverage.json` and
`eval/coverage/live-coverage.md`. The command exits non-zero if in-domain semantic
coverage is below 85%. Keep the full report as evidence; do not substitute the
retrieval-only diagnostic generated by `eval/coverage.py`.

## Retrieval diagnostic (supplementary)

`eval/coverage.py` is retained as a separate retrieval diagnostic. It checks whether
expected source/section chunks appear in top-k retrieval and reports OOD top-score
rates against the API relevance floor. It is useful for debugging retrieval, but it is
not the query-to-golden semantic coverage metric required by E2.

## E2 repair workflow

Preserve the original report and copy the latest E2 report to
eval/coverage/live-coverage-after.json. Then run:

```bash
make coverage-repair
```

This creates eval/coverage/repair-plan.md and repair-plan.json. It prioritizes
uncovered in-domain queries, groups them by topic, shows the nearest existing
golden question, flags exact duplicates, and carries forward the source filename
and section from the live-query dataset.

The tool does not invent page numbers or expected answer phrases and does not
append unverified entries to golden.jsonl. Verify each candidate against its source
passage, add only distinct information needs, then rerun make golden-check and
make live-coverage.
